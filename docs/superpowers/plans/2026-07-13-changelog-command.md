# `/changelog` Release-Notes Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `git-cliff` with an in-session `/changelog` Claude Code command that drafts user-facing release notes (all features, deduped; fixes from milestone ∪ commit refs) into `CHANGELOG.md`'s `[Unreleased]` section for human review.

**Architecture:** A committed slash-command prompt (`.claude/commands/changelog.md`) runs in-session. It reads `git log <lastTag>..HEAD` for `feat` commits, groups them into user-facing feature bullets, and unions milestone-closed issues with commit-referenced issues for the fixes list. It writes a draft into `[Unreleased]` and shows the diff — it never commits, bumps, or tags. `git-cliff` and its config/dependency are removed.

**Tech Stack:** Claude Code slash command (markdown + frontmatter), `git`, `gh` CLI.

## Global Constraints

- Tags are **unprefixed** (`git describe --tags --abbrev=0` → e.g. `2.1.10`).
- Output structure is Keep-a-Changelog: `## [Unreleased]` → `### Features` / `### Bug Fixes`.
- Feature source is `feat` commit **subjects + bodies only** — never diffs or file lists.
- Excluded from Features entirely: `refactor`, `test`, `style`, `chore`, `build`, `ci`, `docs`.
- Fixes = union of milestone-closed issues and `(fix|close|resolve)(e[sd])? #N` commit refs, deduped by issue number, with a fallback bullet for `fix` commits that reference no issue.
- The command produces a **draft only**: no `git commit`, no version bump, no tag.
- Commit messages: no `Co-Authored-By` trailer. Commit to the current branch (`v3-ai`); do not branch.
- Copy: sentence case, en-US, user-facing phrasing (per repo copy style guide).

### Task 2: Author the `/changelog` command

The core deliverable: the slash-command prompt. Verified by a real dry-run against this repo's live history (1292 commits since `2.1.10`, milestone `3.0.0`, 72 issue refs).

**Files:**

- Create: `.claude/commands/changelog.md`

**Interfaces:**

- Consumes: `git` history, `gh` CLI, `CHANGELOG.md`.
- Produces: a `/changelog [version]` command whose in-session behavior is defined by the prompt below.

- [ ] **Step 1: Create the command directory**

Run:

```bash
mkdir -p .claude/commands
```

- [ ] **Step 2: Write the command prompt**

Create `.claude/commands/changelog.md` with exactly this content:

```markdown
---
description: Draft user-facing release notes into CHANGELOG.md [Unreleased]
argument-hint: [version]
allowed-tools: Bash(git log:*), Bash(git describe:*), Bash(gh issue list:*), Bash(gh issue view:*), Bash(gh api:*), Bash(git diff:*), Read, Edit
---

Draft user-facing release notes into the `## [Unreleased]` section of `CHANGELOG.md`.
Produce a **draft only** — never commit, bump the version, or tag.

## Inputs

- Target version: `$1`. If empty, run
  `gh api repos/{owner}/{repo}/milestones --jq '.[].title'` and:
  - exactly one open milestone → use it;
  - zero or multiple → ask the user which version before continuing.
- Last release tag: `git describe --tags --abbrev=0` (tags are unprefixed, e.g. `2.1.10`).

## Gather

1. Commits in range (subjects + bodies, oldest first):
   `git log <lastTag>..HEAD --no-merges --reverse --pretty=format:'%x1e%H%x1f%s%x1f%b'`
   (records separated by 0x1e, fields by 0x1f).
2. Milestone-closed issues:
   `gh issue list --milestone "<version>" --state closed --json number,title --jq '.[] | "\(.number)\t\(.title)"'`
3. Commit-referenced fixed issues: scan every commit subject+body for
   `(?i)(fix|close|resolve)(e[sd])?\s+#(\d+)`; collect the numbers; for each,
   `gh issue view <n> --json number,title,state --jq '"\(.number)\t\(.title)\t\(.state)"'`.

## Build the draft

**Features** — from commits whose subject type is `feat` (ignore
`refactor|test|style|chore|build|ci|docs`):

- List **every distinct user-facing feature**. Group the multiple commits that
  implement one capability into a single bullet.
- Phrase for end users, sentence case, imperative-free (describe the capability,
  not the commit). No scopes, no commit hashes.

**Bug Fixes** — union of milestone issues and referenced issues, **deduped by issue
number**:

- One bullet per issue, using the issue title cleaned of tracker prefixes
  (`Bug:`, `FR:`, `[bug]`, etc.).
- `fix` commits that reference no issue → summarize into their own user-facing
  bullets so nothing is dropped.

Omit a section entirely if it has no entries.

## Write

- Read `CHANGELOG.md`. If a `## [Unreleased]` section exists, replace its body with
  the new draft; otherwise insert a fresh `## [Unreleased]` section immediately after
  the header block (before the first versioned `## [x.y.z]`).
- Use `Edit` to apply the change.

## Report

- Run `git diff CHANGELOG.md` and show it.
- State clearly that this is an unreviewed draft and list any judgement calls
  (features grouped, fix commits with no issue, milestone vs ref-only sources).
- Do **not** commit, bump the version, or tag. Stop and let the user edit.
```

- [ ] **Step 3: Dry-run the command against the live repo**

```

```

This exercises the real range `2.1.10..HEAD`.

- [ ] **Step 4: Verify the draft's shape**

- A `## [Unreleased]` section exists with `### Features` and `### Bug Fixes`.
- **Features:** no bullet paraphrases an internal commit (no "refactor", "add test",

  though multiple `feat` commits back them.
- **Bug Fixes:** includes titles for the milestone-`3.0.0` closed issues **and**
  the issues referenced by `fix #N` in the range; no issue number appears twice.
- Bullets read as end-user phrasing, not commit subjects (no `feat(scope):` prefixes,
  no hashes).
